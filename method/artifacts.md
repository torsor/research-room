# Artifacts and memory

Each artifact should have a distinct purpose:

| Location | Purpose | Maintenance |
|---|---|---|
| `conventions.md` | Definitions and standing assumptions | Update current conventions; explain substantive changes |
| `goals/` | Current research questions | Keep concise and current |
| `journal.md` | Historical reasoning and changes of direction | Append; correct past mistakes in a new entry |
| `notes/` | Reusable evidence, ideas, and unsuccessful work | Preserve substantive history; link superseding work |
| `canonical/` | Current load-bearing claims and their support | Prune and archive withdrawn entries; reassess dependencies |
| Review artifacts, when needed | The exact object reviewed, objections, and outcomes | Preserve version identity and the review trail |
| Optional `HANDOFF.md` | A short operational reminder for resuming unfinished work | Rewrite in place; remove obsolete state |

History and current directions have different jobs. The journal's append-only
rule does not apply to every orientation or task file. Current directions
should not accumulate obsolete instructions under repeated "current" headings.

Link to detailed evidence instead of copying it into every summary. Avoid
updating several status documents with the same account of a single event.

This scaffold has no required handoff file. Use one only when unfinished work
has operational details that the existing artifacts do not make easy to find.
Follow `handoffs.md` for its contents, update rules, and source of authority.
Old handoff versions do not need separate archives merely because they existed.

Keep any imported prior-work archive separate and respect its permissions.
Distinguish what has been independently checked from what is merely available
there. This template does not create or assume a prior-work submodule.
